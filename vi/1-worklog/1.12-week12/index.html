Worklog Tuần 12

Mục tiêu tuần 12:

  • Hoàn thiện toàn bộ báo cáo thực tập tại First Cloud AI Journey (FCAJ).
  • Rà soát và chuẩn hóa Worklog từ tuần 1 đến tuần 12.
  • Kiểm tra sự thống nhất về nội dung và thuật ngữ giữa hai phiên bản tiếng Việt và tiếng Anh.
  • Hoàn thiện Proposal và các tài liệu liên quan đến dự án Student Activity Management & Engagement Analytics Platform.
  • Cập nhật sơ đồ kiến trúc hệ thống theo đúng phạm vi triển khai thực tế.
  • Hoàn thiện API Documentation, User Guide, Test Report và Demo Script.
  • Tổng hợp kết quả Workshop và các minh chứng trình bày dự án nếu đã thực hiện.
  • Hoàn thiện nội dung Self-evaluation để đánh giá kiến thức và kỹ năng đạt được.
  • Hoàn thiện Sharing and Feedback nhằm tổng kết kinh nghiệm trong quá trình thực tập.
  • Rà soát nội dung Blogs Posted và Events Participated theo các hoạt động đã thực tế thực hiện.
  • Kiểm tra toàn bộ website báo cáo thực tập xây dựng bằng Hugo.
  • Kiểm tra cấu trúc thư mục, menu, đường dẫn, hình ảnh và định dạng Markdown trên website.
  • Chuẩn hóa source code và tài liệu trên GitHub Repository.
  • Tổng hợp minh chứng sử dụng 6 dịch vụ AWS gồm Amplify, DynamoDB, S3, IAM, Lambda và CloudWatch.
  • Rà soát tài nguyên đang hoạt động và chi phí AWS.
  • Lưu trữ source code, dữ liệu giả, tài liệu và minh chứng dự án.
  • Chuẩn bị nộp báo cáo cuối kỳ và bàn giao sản phẩm thực tập.

Kết quả dự kiến đạt được tuần 12:

  • 1. Hoàn thiện toàn bộ Worklog 12 tuần:

    Rà soát nội dung theo tiến trình:

    • Tuần 1: AWS Fundamentals, Cloud Computing, AWS CLI và Amazon EC2.
    • Tuần 2: Phân tích yêu cầu, Proposal và thiết kế kiến trúc.
    • Tuần 3: Phát triển Backend FastAPI và các REST API nghiệp vụ.
    • Tuần 4: Nghiên cứu và phát triển DynamoDB/S3 AWS Pilot.
    • Tuần 5: Phát triển React/Vite, Authentication và phân quyền ADMIN/STUDENT.
    • Tuần 6: Registration Import, Evidence Import, CSV/XLSX và Export.
    • Tuần 7: Reconciliation, Participation Status và Analytics Dashboard.
    • Tuần 8: Kiểm thử tích hợp, sửa lỗi và tối ưu giao diện.
    • Tuần 9: Chuẩn bị và triển khai AWS Amplify, FastAPI Demo, Cloudflare Tunnel.
    • Tuần 10: Tích hợp S3, Lambda, IAM, CloudWatch và tổng hợp 6 dịch vụ AWS.
    • Tuần 11: Demo dự án, thu thập Feedback và chuẩn hóa tài liệu.
    • Tuần 12: Hoàn thiện báo cáo, kiểm tra website Hugo và bàn giao.

    Đảm bảo:

    • Các tuần có nội dung liên tục và hợp lý.
    • Công việc phản ánh đúng tiến độ thực tế.
    • Ngày thực hiện được đối chiếu với nhật ký công việc và Git history.
    • Bản tiếng Việt và tiếng Anh thống nhất.
    • Không ghi những chức năng chưa triển khai thành kết quả đã hoàn thành.

  • 2. Hoàn thiện Project Proposal:

    Các nội dung chính:

    • Problem Statement.
    • Project Objectives.
    • Project Scope.
    • Target Users.
    • Functional Requirements.
    • Non-functional Requirements.
    • Business Rules.
    • Data Sources.
    • Technology Stack.
    • AWS Architecture.
    • Data Flow.
    • Testing Strategy.
    • Limitations.
    • Future Development.

    Proposal cần mô tả đúng hệ thống đang được phát triển thay vì chỉ thể hiện kiến trúc dự kiến ban đầu.

  • 3. Hoàn thiện AWS Architecture Diagram:

    Phân biệt ba thành phần chính:

    Web Application:

    User → AWS Amplify Hosting → Cloudflare Tunnel → FastAPI → SQLite Demo

    AWS Data Pilot:

    FastAPI Test Modules → Amazon DynamoDB / Amazon S3

    Serverless CSV Processing Demo:

    Amazon S3 (Input) → AWS Lambda → Amazon S3 (Output)

    Các dịch vụ hỗ trợ:

    • AWS IAM cấp quyền thực thi và truy cập S3 cho Lambda.
    • Amazon CloudWatch theo dõi log và kết quả thực thi.

    Xác định rõ 6 dịch vụ AWS:

    • AWS Amplify.
    • Amazon DynamoDB.
    • Amazon S3.
    • AWS IAM.
    • AWS Lambda.
    • Amazon CloudWatch.

    Không thể hiện Cognito, API Gateway, Glue, Athena hoặc QuickSight là những dịch vụ đã được triển khai thực tế.

  • 4. Hoàn thiện tài liệu kỹ thuật:

    • Project README.
    • Architecture Documentation.
    • API Documentation.
    • User Guide.
    • Test Report.
    • Demo Script.
    • AWS Configuration Notes.
    • Project Evidence.

    Tài liệu cần trình bày được cách cài đặt, cấu hình, chạy ứng dụng và kiểm tra các chức năng.

  • 5. Hoàn thiện tài liệu về chức năng hệ thống:

    Các nhóm chức năng:

    • Authentication và Authorization.
    • Activity Management.
    • Student Account Management.
    • Registration Import.
    • Real-time Check-in/Check-out.
    • Evidence Import.
    • Reconciliation.
    • Participation Confirmation.
    • Analytics Dashboard.
    • Export Results.

    Với mỗi chức năng cần thể hiện:

    • Mục đích.
    • Quy trình xử lý.
    • Nhóm người dùng được phép sử dụng.
    • API hoặc thành phần kỹ thuật liên quan.
    • Các trường hợp dữ liệu không hợp lệ.
    • Giới hạn của phiên bản MVP.

  • 6. Hoàn thiện Workshop và Demo Materials:

    • Tổng hợp nội dung trình bày đã thực hiện, nếu có.
    • Chuẩn bị slide mô tả Problem Statement và Solution.
    • Hoàn thiện sơ đồ kiến trúc.
    • Tổng hợp luồng nghiệp vụ để minh họa.
    • Chuẩn bị hình ảnh giao diện Web Application.
    • Tổng hợp minh chứng từ AWS Console.
    • Ghi nhận những kết quả thực tế và các phản hồi liên quan.

  • 7. Tổng hợp minh chứng cho 6 dịch vụ AWS:

    Dịch vụMinh chứng cần tổng hợp
    AWS AmplifyApp, Branch, Deployment Status và Website URL
    Amazon DynamoDBTables, Pilot Configuration và kết quả kiểm thử
    Amazon S3Bucket, Input CSV và Output JSON
    AWS IAMLambda Execution Role và Inline Policy
    AWS LambdaFunction Configuration và Test Result
    Amazon CloudWatchLog Group, Log Stream và Execution Metrics

    Các minh chứng được kiểm tra để không làm lộ Access Key, Secret Key, Token hoặc dữ liệu cá nhân.

  • 8. Hoàn thiện Self-evaluation:

    Kiến thức đã nghiên cứu:

    • AWS Cloud Fundamentals.
    • AWS Global Infrastructure.
    • Amazon EC2.
    • Amazon DynamoDB.
    • Amazon S3.
    • AWS Amplify.
    • AWS Lambda.
    • AWS IAM.
    • Amazon CloudWatch.
    • Serverless Architecture.
    • REST API Design.
    • Authentication và Authorization.
    • Data Processing và Analytics.

    Kỹ năng thực hành:

    • Python/FastAPI Backend Development.
    • React/Vite Frontend Development.
    • SQLite Database Management.
    • CSV/XLSX Processing.
    • REST API Testing.
    • Git và GitHub.
    • AWS Resource Configuration.
    • Debugging và Troubleshooting.
    • Technical Documentation.
    • Presentation và Team Communication.

    Phần Self-evaluation cần phân biệt rõ kiến thức đã nghiên cứu với kỹ năng đã trực tiếp thực hành.

  • 9. Hoàn thiện Sharing and Feedback:

    • Tổng kết những trải nghiệm trong thời gian thực tập.
    • Ghi nhận khó khăn khi tiếp cận AWS và xây dựng hệ thống.
    • Đánh giá hiệu quả của việc học qua tài liệu và bài thực hành.
    • Ghi nhận góp ý thực tế từ người hướng dẫn, nếu có.
    • Tổng hợp những bài học về kiến trúc, phát triển phần mềm và kiểm soát chi phí.
    • Đề xuất những cải tiến cho quy trình học tập và triển khai dự án.

  • 10. Rà soát Blogs Posted và Events Participated:

    • Kiểm tra các bài Blog đã thực tế đăng tải.
    • Bổ sung đúng tiêu đề, thời gian và nội dung.
    • Không ghi những bài Blog chưa xuất bản là đã đăng.
    • Rà soát các Workshop, Event hoặc hoạt động đã tham gia.
    • Bổ sung hình ảnh và minh chứng khi có.
    • Kiểm tra sự thống nhất giữa các mục báo cáo.

  • 11. Kiểm tra website báo cáo Hugo:

    • Kiểm tra nội dung ở cả hai ngôn ngữ.
    • Kiểm tra cấu trúc YAML Front Matter.
    • Kiểm tra title, date, weight, chapter và pre.
    • Kiểm tra thứ tự hiển thị của các tuần.
    • Kiểm tra Markdown Table và các danh sách.
    • Kiểm tra liên kết và hình ảnh.
    • Kiểm tra menu điều hướng.
    • Kiểm tra khả năng hiển thị trên màn hình máy tính và điện thoại.
    • Xác định những trang còn nội dung mẫu hoặc thiếu minh chứng.

  • 12. Chuẩn hóa GitHub Repository:

    • Kiểm tra cấu trúc Frontend/Backend.
    • Kiểm tra source code và dependencies.
    • Kiểm tra README và hướng dẫn chạy hệ thống.
    • Rà soát .gitignore.
    • Không đưa Credentials, Token hoặc file .env chứa bí mật lên GitHub.
    • Lưu lại source code và tài liệu phù hợp với phiên bản cuối.

  • 13. Rà soát tài nguyên và chi phí AWS:

    • Kiểm tra AWS Amplify Hosting.
    • Kiểm tra các bảng DynamoDB Pilot.
    • Kiểm tra S3 Bucket và dữ liệu thử nghiệm.
    • Kiểm tra Lambda Function và cấu hình thực thi.
    • Kiểm tra IAM Role và Policy liên quan.
    • Kiểm tra CloudWatch Logs và Log Retention.
    • Rà soát AWS Billing.
    • Xem xét xóa tài nguyên thử nghiệm không còn cần thiết sau khi đã lưu minh chứng.
    • Không xóa tài nguyên đang được sử dụng hoặc cần thiết cho việc Demo/bàn giao.

  • 14. Tổng hợp những hạn chế của hệ thống:

    • Backend demo hiện vẫn phụ thuộc vào máy tính chạy local.
    • Cloudflare Quick Tunnel có URL tạm thời.
    • SQLite chưa phải giải pháp lưu trữ dành cho môi trường Production quy mô lớn.
    • DynamoDB mới được tích hợp và thử nghiệm ở phạm vi Pilot.
    • Lambda CSV Processor đang là quy trình Serverless Demo độc lập.
    • Camera QR Scanner chưa được xác nhận hoàn thiện.
    • Dữ liệu đăng ký chưa tích hợp trực tiếp với University Portal.
    • Chưa thực hiện kiểm thử tải lớn trong môi trường Production.
    • Một số trường hợp đối soát vẫn cần ADMIN xác nhận.

  • 15. Xác định hướng phát triển trong tương lai:

Khó khăn dự kiến và bài học cần tổng kết:

  • Tổng hợp tài liệu: Các tài liệu được viết ở nhiều giai đoạn có thể sử dụng thuật ngữ hoặc mô tả kiến trúc khác nhau, cần rà soát trước khi nộp.
  • Đối chiếu tiến độ: Worklog phải phản ánh công việc thực tế, không tự động xem mọi mục tiêu là đã hoàn thành.
  • Báo cáo song ngữ: Hai phiên bản tiếng Việt và tiếng Anh cần thống nhất về nội dung, ngày tháng và kết quả.

  • Website Hugo: Front Matter, đường dẫn, hình ảnh và định dạng Markdown cần được kiểm tra trực tiếp sau khi Build.
  • Bảo mật dữ liệu: Không công khai thông tin xác thực hoặc dữ liệu cá nhân trong mã nguồn và hình ảnh báo cáo.
  • Kiểm soát chi phí: Cần theo dõi tài nguyên AWS ngay cả khi đã kết thúc giai đoạn thực hành.
  • Bàn giao dự án: Người tiếp nhận cần có đủ tài liệu để hiểu kiến trúc, cài đặt và chạy hệ thống mà không phụ thuộc hoàn toàn vào người phát triển ban đầu.
