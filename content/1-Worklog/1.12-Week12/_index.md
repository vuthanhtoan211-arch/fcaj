### Expected Challenges and Lessons Learned:

* **Documentation consolidation:** Documents written at different stages may use inconsistent terminology or architecture descriptions. These inconsistencies must be reviewed and resolved before submission.

* **Progress verification:** The Worklog must accurately reflect the actual work completed. Planned objectives must not automatically be treated as completed outcomes.

* **Bilingual reporting:** The Vietnamese and English versions must remain consistent in terms of content, dates, and reported results.

* **AWS evidence:** It is important to clearly distinguish between active services, AWS Pilot implementations, and services that have only been studied.

* **Hugo website:** Front Matter, links, images, and Markdown formatting must be verified directly after building the website.

* **Data security:** Credentials and personal data must not be publicly exposed in the source code or report screenshots.

* **Cost control:** AWS resources must continue to be monitored even after the hands-on practice phase has ended.

* **Project handover:** The recipient must have sufficient documentation to understand the architecture, install, configure, and run the system without relying entirely on the original developer.
